## §0 이전의 성격 — "옮기는 것"이 아니라 "막힌 걸 여는 것"

우리 스크립트 83개는 **stdlib 중심**이라 이식 자체는 거의 공짜다(아래 §6에서 실제로 걸린 이식 결함은 3건뿐이었다).
로컬 이전의 값어치는 **데이터센터 IP 때문에 닫혀 있던 경로가 열리는 것**이고, 그게 전부다.
⇒ **"로컬 가면 좋아진다"를 막연히 쓰지 말 것.** 아래 §1이 열리는 것과 안 열리는 것의 확정 목록이다.

**첫 세션에 딱 하나만 돌린다면 `local_doctor.py`** — 이 기계가 레포를 돌릴 조건을 갖췄는지 네트워크 없이 23항목 점검한다(§2d 0단계).

### 2a-2. ★ `python3` 런처 — 이 이전의 가장 큰 지뢰 (8/31 발견)

**윈도우 네이티브엔 `python3`가 없다.** 공식 인스톨러는 `python.exe`·`py.exe`만 깐다.
그런데 우리 **지시층은 전부 `python3 ...`로 스크립트를 부른다** — 실측 **561곳**
(skills 460 · agents 49 · docs 49 · hooks 3) + `settings.json` 권한 허용 25줄.
⇒ 파이썬을 제대로 깔아도 **에이전트의 호출이 통째로 실패**하고, `settings.json`의
`Bash(python3 ...)` 허용이 하나도 안 걸려 **매 호출이 권한 프롬프트**가 된다.

§6이 잡은 이식 결함 3건은 **코드층**이었다. 이건 **지시층**이라 grep 대상이 달랐고 그래서 새 나갔다.

**해법 = 561곳을 고치지 말고 심(shim) 하나를 깐다.** (맥·WSL로 가면 심은 그냥 무시된다)

Git Bash에서 1회:
```bash
mkdir -p ~/bin
printf '#!/bin/sh\nexec py -3 "$@"\n' > ~/bin/python3
chmod +x ~/bin/python3
grep -q 'HOME/bin' ~/.bashrc || echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
```
확인: 새 Git Bash 창에서 `python3 -V` → `Python 3.11+`

⚠️ **Claude Code는 비대화형 셸로 Bash 도구를 돌린다** — `~/.bashrc`가 안 읽힐 수 있다.
그때는 PATH를 **시스템 환경변수**(`%USERPROFILE%\bin`)에 넣고, 거기에
확장자 없는 `python3` **와** `python3.cmd`(`@py -3 %*`)를 **둘 다** 둔다.
`local_doctor.py`의 「`python3` 런처」 항목이 FAIL이면 아직 안 걸린 것이다.

## §3 무인 루틴 — 두 경로 (정훈 8/29: **아직 미정, 양쪽 정리만**)

현행 = 웹 Claude Code **Routines** 5개(R1 10:00 / R2 16:00 / R3 토 09:00 / R4a 20:00 / R4b 21:15, 전부 KST).

### 경로 A — 하이브리드(루틴은 웹 유지)
- **장점**: 지금 도는 구조를 아무것도 안 건드린다. **머신이 꺼져 있어도 보고서가 난다**(윈도우 데스크톱을 24시간 켜두는 건 현실적이지 않다). 무인 세션 권한·완료 알림(push)이 이미 검증됨.
- **단점**: 로컬에서 열린 경로(KRX 공매도·yt-dlp 프레임)를 **무인 루틴은 못 쓴다** — 웹 세션이 도니까. 로컬은 대화형·수집 전담이 된다.
- **연속성**: 양쪽 다 origin/main을 정본으로 쓰므로 충돌 없음. 단 **로컬 작업분을 main에 밀어놓지 않으면 다음 웹 루틴이 옛 상태로 시작**한다(연속성 규약 그대로, 오히려 더 엄격해짐).

### 경로 B — 전부 로컬(cron/작업 스케줄러가 `claude`를 무인 호출)
- **선행 확인 3건** (미확인 — 월요일에 실측해야 함):
  1. 로컬 Claude Code CLI의 무인 실행(`claude -p`)에서 **권한 프롬프트가 안 뜨는지** (웹 무인 세션과 권한 모델이 다르다).
  2. **완료 알림 경로** — 웹 Routines의 push 알림을 무엇이 대체하나(R2/R4는 push ON이 전제).
  3. **머신 상시 가동** — 10:00·16:00·20:00·21:15에 깨어 있어야 한다. 윈도우 절전/업데이트 재부팅이 루틴을 조용히 죽인다.
- **장점**: 로컬 전용 경로가 무인 루틴에도 들어온다.
- **단점**: 위 3건이 전부 새 작업이고, **실패가 조용하다**(웹 Routines는 실패가 기록에 남는다).
- **필요 작업**: R1~R4b 프롬프트를 `claude -p`용으로 옮기고 `docs/routines.md` §스케줄 등록 표를 갈아끼움.

**PM 권고**: **월요일엔 경로 A로 시작.** 이유 = 이전의 목적(§1)이 *막힌 경로 열기*이고 그건 대화형 세션만으로 전부 달성된다. 루틴까지 같이 옮기면 **무인 실패가 조용해지는 위험**을 검증 없이 떠안는다. 경로 B는 §3의 선행 확인 3건을 실측한 뒤 별건으로 결정.

## §5 2단계 — 맥 이관 & Mac mini 사양

### 5a. 우리 워크로드의 실제 부하 (사양 판단의 근거)
- 스크립트는 **네트워크 I/O 바운드**다 — Yahoo·EDGAR·DART·FRED 응답 대기가 시간의 대부분(8/29 api_health: 3ms~11초). CPU 연산은 `portfolio_stats`의 상관행렬·`garch` 적합 정도로 **수 초 규모**.
- **LLM은 전부 클라우드에서 돈다.** 로컬 추론이 없으니 **GPU·Neural Engine 성능은 우리에게 무의미하다.**
- 무거운 동시 실행 = Chromium 1개(`web_shot`) + 파이썬 몇 개.
- 레포 전체 **39MB**(.git 13MB · data 14MB · docs 5MB). 전체 히스토리로 풀어도 수백 MB 수준.

### 5b. ⇒ 권고: **베이스 모델로 충분하다. 돈은 램·상시가동에만 쓴다.**
- **칩**: 최하위 티어로 충분. M6 vs M5 Pro의 차이(CPU 코어·AI 성능)는 우리 부하에서 **체감 0에 가깝다.** M5 Pro는 낭비다.
- **메모리**: **16GB면 충분, 24GB면 여유.** 근거 = Chromium + 파이썬 몇 개. 램은 나중에 못 늘리니 24GB가 안전마진이지만, 16GB로 못 돌 이유는 우리 워크로드에 없다.
- **저장**: **256GB로 충분**(레포 39MB). 다만 유튜브 프레임·스크린샷 캐시가 쌓이면 512GB가 편하다. 외장 SSD로도 해결된다.
- **진짜 중요한 건 사양이 아니라 상시가동**: 경로 B(§3)를 택한다면 맥미니는 **켜둔 채 절전만 끄면 되는 기계**라 데스크톱보다 유리하다. 이게 맥미니를 사는 유일한 실질 이유다.

### 5c. 현행 라인업 (2026-08-29 확인)
- Apple이 **2026-08-25 신형 Mac mini 발표** — **M6**(첫 2nm·12코어 CPU) 및 **M5 Pro**. **배송 시작 9/22**(사전주문 중). [1차 출처 = Apple Newsroom]
- 미국 시작가 **$899**(M6·16GB·256GB) / **M5 Pro $1,699**(24GB·512GB) — 2차 매체(TechCrunch·9to5Mac) 기준.
- **⚠️ 한국 원화가 미확인** — Apple 코리아 페이지에서 원화 표기를 확보하지 못했다. **$899 × 환율로 추산하지 말 것**(부가세·현지 가격정책이 다르다). 구매 직전에 apple.com/kr에서 직접 확인.
- **타이밍**: 9/22 배송이라 **월요일 착수와는 무관**하다. 윈도우로 1단계를 돌려보고, 경로 B가 필요하다고 판단될 때 사는 순서가 맞다. 구형 M4를 할인가에 잡는 선택지도 우리 부하에선 **성능상 손해가 없다.**
