## 0. 가장 큰 수확 — 증권사 리포트 원장이 2주간 멈춰 있었다

`broker_reports.py`의 **누적 인덱스가 7/30에서 정지**해 있었다. 원인은 데이터가 없어서가 아니라 **배선**이다:

```python
if a.fetch:            # ← PDF 본문을 통째로 받는 무거운 플래그
    ...
    save_index(rows)   # ← 저장이 이 안에만 있었다
```

`--fetch`는 무거워서 루틴이 안 쓴다 → **조회는 최신을 보여주는데 저장이 안 됐다.**
그동안 `--targets`(누적 인덱스를 읽어 목표가 컨센서스를 계산)는 **2주 묵은 데이터로 답하고 있었다.**

**실측 피해 — LG전자**

| | 수정 전(7/30 원장) | 수정 후(복구) |
|---|---|---|
| 표본 | n=2 | **n=5** |
| 레인지 | 240,000 단일 | **180,000 ~ 250,000** |
| 중앙 | 240,000 | 240,000 |
| 최신 | 유안타 240,000(7/8) | **iM 250,000(8/13)** |

누락돼 있던 것: IBK 180,000(7/31) · SK증권 180,000(7/31) · iM 250,000(8/13).

**수정**: `save_index()`를 `--fetch` 블록 **밖으로** 옮겨 상시 호출. 본문 다운로드만 `--fetch`에 남겼다.
**⇒ 저장은 조회의 부산물이어야 한다.** 오늘 정리한 **(B)계열 '죽은 배선'**의 네 번째 사례다.
복구 결과 **누적 73 → 95건**(8/1 이후 10건 신규).

**★자기 정정**: 오늘 낮 v75에 *"LG전자 익절가 240,000원이 컨센 상단(iM 250,000·메리츠 260,000)보다 낮다"*고 썼는데,
정확히는 **240,000 = 컨센 중앙값**이다(하단 180,000·상단 250,000). 메리츠는 목표가 파싱이 `0.0`으로 실패해 있어
power 데스크가 인용한 "적정주가 260,000"은 원장에 없다. **익절가는 낮지 않다 — 중앙이다.** 보고서 표 교정 완료.
